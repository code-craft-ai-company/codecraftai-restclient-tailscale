# Design

## Overview

`TailscaleClient` is a `RestClientBase` subclass. It exposes Tailscale's API as
typed Python methods grouped by domain. The class hierarchy follows the
`apigroups/*Group` pattern landed during the M1 `restapigroup-enhancements` work.

The client implements `IVPNControlPlane` from `codecraftai-interfaces`. Once this
package is published, the M3-landed `codecraftai-interop/vpn/tailscale/tailscalecontrolplane.py`
will be reduced to a one-line `from ccai.restclient.tailscale import TailscaleClient as TailscaleControlPlane`
with a `DeprecationWarning`.

## Architecture

```
┌────────────────────────────────────────────────────────────┐
│ TailscaleClient(RestClientBase)                            │
│                                                            │
│   credential: TailscaleOAuthCredential | TailscaleAuthKeyCredential
│   _bearer: Optional[BearerToken]   (cached)                │
│                                                            │
│   .devices    → DevicesGroup     (RestApiGroup)            │
│   .keys       → KeysGroup        (RestApiGroup)            │
│   .acls       → AclsGroup        (RestApiGroup)            │
│   .tailnets   → TailnetsGroup    (RestApiGroup)            │
│   .dns        → DnsGroup         (RestApiGroup)            │
│   .posture    → PostureGroup     (RestApiGroup)            │
│                                                            │
│   # IVPNControlPlane methods delegate to groups            │
│   mint_authkey()  → self.keys.mint(...)                    │
│   list_devices()  → self.devices.list(...)                 │
│   delete_device() → self.devices.delete(...)               │
│   apply_acl()     → self.acls.put(...)                     │
└────────────────────────────────────────────────────────────┘
```

## Data Model

The `IVPNControlPlane` methods accept and return the protocol-declared dataclasses
(`VPNDeviceRecord`, etc.). The api-group methods accept and return the OpenAPI-generated
`SchemaObject` classes from `tailscale-openapi-import`. Translation between the two
happens in thin adapter methods on `TailscaleClient` — the protocol surface stays
provider-neutral; the group surface is faithful to the upstream API.

## Testing Strategy

**Example-based tests:**
- Construct with each credential type; verify wiring.
- Mock HTTP fixtures for each api-group method; verify URL composition, body shape, headers.
- Verify `isinstance(TailscaleClient(...), IVPNControlPlane)` at runtime.
- OAuth lifecycle: lazy mint, cache hit, 401 → mint-once → retry, second 401 raises.

**Property tests (hypothesis):**
- URL composition is total: for any valid (`device_id`, `tailnet`, query params) combo, the constructed URL is well-formed and matches the OpenAPI path template.
- Paging: `iter(...)` over any sequence of cursor-paged responses visits every record exactly once and terminates.
- Bearer cache: for any sequence of (call, time-advance, 401-or-not) events, the bearer is minted no more than once per expiry window.
- Adapter symmetry: round-trip from `VPNDeviceRecord` ↔ `TailscaleDevice` is information-preserving for the fields both share.
